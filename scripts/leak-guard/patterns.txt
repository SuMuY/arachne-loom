# Sensitive-data patterns for the leak guard. One regex per line.
# Blank lines and lines starting with '#' are ignored. Matched case-insensitively
# against every tracked text file and the OOXML parts of .docx/.xlsx/.pptx.
#
# Keep this file APPEND-ONLY. Two kinds of entries:
#   1. STRUCTURAL patterns — catch shapes you have not enumerated yet.
#   2. EXACT strings — known real identifiers that must never ship.
#
# The structural examples below are starting points. Tune them to your domain,
# and be careful that generic shapes don't match machine-generated hex IDs
# inside OOXML (a 6-digit + 2-hex-letter id like 0-0-0-0-0-1-F-F is NOT real
# data; the trial-ID example excludes pure-hex suffixes for this reason).

# --- structural shapes (generic starting set — edit for your project) ---
# ID-like: 6 digits + a letter suffix containing a non-hex letter (G-Z),
# so machine-generated hex ids are ignored.
\b\d{6}[A-Z]*[G-Z][A-Z]*\b
# Internal project codes like AB-123 (adjust the prefix/width to taste).
\b[A-Z]{2}-\d{3}\b
