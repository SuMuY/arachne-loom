# 全文列表格式统一

编译器现在使用 Word 原生列表。全文的有序列表共享一套间距，无序列表共享另一套间距；每个列表独立编号。有序列表起始值由输入决定，后续序号由 Word 连续生成。

可在 profile 中设置（单位：磅，72 磅 = 1 英寸）：

```json
"listStyle": {
  "unordered": {"markerPt": 18, "textPt": 42},
  "ordered": {"markerPt": 18, "textPt": 54}
}
```

- `markerPt`：符号或序号相对页面正文左边界的位置。
- `textPt`：正文首行和续行的统一起点，必须大于 markerPt。
- 两者之差是编号占用的悬挂区域；默认两类都为 18/42。
- 正文起点通过制表位与悬挂缩进统一，不能用填充空格代替。
- 序号宽度会随数字位数和字体变化。要保证多位数仍有间距，应为实际最长序号保留足够的悬挂区域。

例如，正文在 42pt 开始时，长列表项换行后也从 42pt 开始，不退回左边界或圆点位置。统一的是对齐位置；不同宽度序号右侧的可见空白会随数字宽度变化。

## 输入

Markdown 支持 `- `、`+ `、`* `、`• ` 无序列表，以及 `1. `、`1) ` 有序列表。同类型连续非空行形成一个列表；空行结束当前列表，下一个列表重新开始。圆点后至少有一个空白才识别为列表。已粘连的 `•文字` 应由语义编写入口确认后整理成 `- 文字`，不能自动改写正文中的普通圆点。

目前支持单层列表；检测到缩进的列表项会报错，避免把嵌套关系抹平。列表内的交叉引用与正文共用 REF 实现。

Canonical Model 示例：

```json
{
  "type": "list", "kind": "ordered", "start": 9,
  "items": [
    {"inlines": [{"type": "text", "text": "第一个列表项"}]},
    {"inlines": [{"type": "text", "text": "第二个列表项"}]}
  ]
}
```
