# 医学写作格式规则与 CSR 配置

本文把当前已实现的格式能力分为两层：第一层是医学写作文件可共用的 Word 格式机制；第二层是 CSR profile 当前选择的具体参数。这里的“共用”表示同一机制可用于医学文件，不表示所有医学文件必须采用同一组版式数值。

## 第一层：医学写作共用格式规则

### 1. 输入与内容保留

- 生成流程读取明确结构化的 Markdown 或 Canonical Model JSON，再生成新的 `.docx`。
- 输入模型明确提供标题、正文段落、列表、表格、图片、题注和交叉引用目标；编译器按这些结构生成 Word 对象。
- 格式生成不授权改写科学正文或表格数据。
- 图片使用声明资源目录内的 PNG、JPG 或 JPEG；不接受越出资源目录的图片路径或外部 URL。

### 2. 标题与章节编号

- 标题使用 Word 原生 Heading 1–9 样式，模型中的标题级别范围为 1–9。
- 标题编号由 Word 多级编号定义生成，当前编号形式是十进制阿拉伯数字点分层级，例如一级 `1`、二级 `1.1`、三级 `1.1.1`。
- 章节号由输入模型的 `numberPath` 提供。比如 CSR 一级章节可输入 `1`，下级标题沿用对应章节路径；CTD 可提供 `2.7.3` 这样的路径。
- 每级标题绑定到 profile 对应的 Word 样式角色，例如 `headingLevel1` 对应 Heading 1。
- 生成时会设置标题段落与后文保持在一起，降低标题落在页末、正文移到下一页的情况。
- 引擎支持可配置的标题编号缩进：`basePt` 为一级起点，`incrementPt` 为每深入一级增加的距离，`hangingPt` 为编号与正文之间的悬挂宽度。当前 CTD/CSR profile 没有提供该缩进对象，具体标题外观由所用 Word 基础模板中的 Heading 样式决定。

### 3. 有序与无序列表

- 列表由 Word 原生多级编号对象生成；序号和项目符号不是正文字符。
- 每个列表块最多支持 9 层（level 0–8），每项可声明层级、类型（有序或无序）和起始序号。
- 有序列表目前使用十进制编号；全有序的多级编号会形成 `1.`、`1.1.`、`1.1.1.`。无序列表使用项目符号。
- 列表可以在不同层级组合有序和无序类型；同一列表块的同一层级不能中途改变类型。
- 列表必须从第 0 层开始，层级逐步递进，不能从 0 直接跳到 2。Markdown 输入以每层两个空格表达嵌套。
- `listStyle` 可设置编号/符号位置 `markerPt` 和正文起点 `textPt`。每深入一级，两者分别增加 18 磅。profile 未提供 `listStyle` 时，生成器使用 `markerPt=18`、`textPt=42` 的默认值。
- Word 的制表位和悬挂缩进使项目内容换行后与正文起点对齐。

### 4. 表格

- 只支持矩形表格：每行列数相同；当前 Canonical Model 要求一个表头行。
- 生成的 Word 表格使用 `Table Grid` 样式，并把首行标记为重复标题行，供表格跨页时重复显示。
- 合并单元格或列数不齐的表格不在当前支持范围内。

### 5. 图片

- 按结构化输入中的图片资源路径插入图片。
- 图片段落居中；图片后保留配置在生成器中的段落间距，并按结构生成图题。

### 6. 图表题注编号

- 表和图分别使用 Word 原生 `SEQ` 域产生序号。
- 章节标识使用 Word 原生 `STYLEREF` 域，从当前配置指定的标题样式读取；章节级别及序号重置级别由文档类型 profile 决定。
- 题注包含本地化标签、章节号、分隔符、序号和标题文字。例如中文可显示为“表 1-1 受试者分布”。
- 表题和图题分别具有独立序列。改变 Word 中对象次序后，需要更新域以重新计算显示编号。
- 题注书签只覆盖标签与编号，不包含题名；正文交叉引用可据此只显示标签和编号。

### 7. 正文交叉引用

- 对图表对象的正文引用使用 Word 原生 `REF` 域，并链接到相应题注书签。
- profile 可设置引用颜色和下划线；是否在 Word 更新域、保存并重开后维持外观，应按目标 Word 环境验收。
- 输入中的引用目标必须对应一个已定义的表或图对象，否则校验失败。

### 8. 目录

- 可生成正文目录、表目录和图目录。
- 正文目录默认包含 Heading 1–3；任务可明确指定其他深度。
- 表目录和图目录是否生成以及目录排列顺序由 profile 控制。
- 目录使用 Word 域，打开文档后应在 Word 中更新域以生成或刷新目录项。

### 9. 已有 DOCX 的有限格式规范化

- `loom normalize` 可调整已有 DOCX 中可识别的 Word 原生 Heading 1–9 段落，以及原生有序/无序列表的缩进几何位置。
- 标题几何位置可由 `headingStyle.indentation` 配置；未配置时使用一级起点 0 磅、逐级增加 18 磅、悬挂宽度 24 磅。
- 列表几何位置使用 profile 的 `listStyle`，未配置时使用上述默认列表位置。
- 操作要求源文件与输出文件不同；正文段落文字会保留。
- 该路径不会把手打的 `1.` 或 `•` 转成 Word 原生编号，也不会从字号或外观猜测标题，不会重建任意 Word 文档。

### 10. 结构校验与 Word 验收

- 编译前校验标题层级跳级、列表层级、ID 唯一性、表格矩形结构、图片路径及图表引用目标。
- 生成后独立检查 Word 文档中的域、书签、对象清单和结构问题。
- 静态 XML/结构检查不能代替桌面 Word 验收。正式使用前应在 Word 中更新域，检查标题/列表缩进、题注编号、引用跳转及保存重开后的稳定性。

## 第二层：CSR 当前配置

CSR 配置有中文和英文两个版本：`profiles/csr/zh-CN/config.json`、`profiles/csr/en-US/config.json`。两者的章节题注规则相同；样式名称和显示标签按语言区分。

CSR profile 是从现有 CTD profile 复制出的起始配置，不代表所有 CSR 模板都应采用这些页面和样式数值。当前明确按 CSR 调整的是表、图题注使用一级标题作为章节号，并在一级标题处重置序号。以下列出的是代码与配置核对结果；静态结构核对不等于已完成桌面 Word 的视觉验收。

### 1. 页面与正文

| 配置项 | 当前值 | 执行情况 |
|---|---|---|
| 页面大小 | Letter，21.59 × 27.94 厘米 | 生成器实际设置 |
| 页面方向 | 纵向 | 当前生成器以 Letter 默认纵向页面生成；profile 中 `orientation` 字段本身没有独立执行逻辑 |
| 上、下、左、右页边距 | 各 2 厘米 | 生成器实际设置 |
| 正文字体 | Times New Roman | 写入 Normal 样式；同时写西文和东亚字体名 |
| 正文字号 | 12 磅 | 写入 Normal 样式 |
| 正文行距 | 配置写 1.5 倍 | 当前生成器未应用该字段 |
| 正文对齐 | 配置写两端对齐 | 当前生成器未应用该字段 |
| 正文段后距 | 配置写 6 磅 | 当前生成器未应用该字段 |

因此，CSR profile 中行距、正文对齐和段后距是配置文件里存在的值，不应描述成当前生成结果已保证的正文格式。

### 2. 标题

- 配置 Heading 1–9 九个标题角色。
- 中文 profile 映射为“标题 1”至“标题 9”；英文 profile 映射为 `heading 1` 至 `heading 9`。底层 Word 样式 ID 分别为 `Heading1` 至 `Heading9`。
- 标题编号采用第一层说明中的十进制点分多级编号。CSR 一级章节号由输入模型提供，例如 `1` 至 `16`；子标题沿章节层级编号。
- profile 设置所有标题不倾斜。
- CSR profile 没有设置 `headingStyle.indentation`；标题视觉样式和缩进继承自实际使用的 Word 基础模板。

### 3. CSR 图表题注规则

| 对象 | 显示标签 | 位置 | 章节号取自 | 序号重置 | 示例形式 |
|---|---|---|---|---|---|
| 表 | 中文“表”；英文“Table” | 表格上方 | Heading 1（CSR 一级章节号） | Heading 1，即每个一级章节重新计数 | 表 1-1、表 1-2；进入第 2 章后从表 2-1 开始 |
| 图 | 中文“图”；英文“Figure” | 图片下方 | Heading 1（CSR 一级章节号） | Heading 1，即每个一级章节重新计数 | 图 1-1、图 1-2；进入第 2 章后从图 2-1 开始 |

- 表和图使用各自独立的序列：表的增加不会改变图的序号，图的增加也不会改变表的序号。
- 两种题注均以连字符 `-` 连接章号和序号。
- 配置字段中，表和图的 `chapterStyleRole` 均为 `headingLevel1`，`sequenceResetLevel` 均为 `1`；生成的 Word 域分别使用 `STYLEREF` 读取 Heading 1 章号、使用 `SEQ ... \s 1` 在一级标题处重置。
- 这里的关键 CSR 选择是“题注章号取一级标题、序号按一级标题重置”。`STYLEREF`/`SEQ` 是共用 Word 机制；取一级还是三级、四级由 profile 参数决定。

### 4. 题注外观

| 配置项 | 当前值 | 执行情况 |
|---|---|---|
| 字号 | 12 磅 | 生成器实际设置 Caption 样式 |
| 字重 | 加粗 | 生成器实际设置 |
| 斜体 | 不倾斜 | 生成器实际设置 |
| 对齐 | 居中 | 生成器实际设置 |
| 段前距 | 0 磅 | 生成器实际设置 |
| 段后距 | 6 磅 | 生成器实际设置 |
| 行距 | 单倍 | 生成器实际设置 |

### 5. 表格配置

- profile 文件写有字号 10.5 磅、自动适应窗口、三线表、重复表头和允许局部覆盖等字段。
- 当前生成器实际使用 `Table Grid` 样式，并启用首行重复；`fontSizePt`、`layout`、`style: threeLine` 和 `allowLocalOverrides` 没有作为 CSR profile 参数应用。因此 CSR 当前实际输出不能保证为 10.5 磅三线表。

### 6. 交叉引用与目录

- 图表正文交叉引用采用 Word `REF` 域，要求可点击；配置颜色为蓝色、带下划线。结构上生成链接字段；显示效果需在目标 Word 版本更新域后核验。
- 正文目录默认到 Heading 3；同时启用表目录和图目录。
- 默认目录顺序是正文目录、表目录、图目录。
- 这些目录字段由 Word 更新，profile 设定的是目录是否启用和正文目录层级。

## 使用 CSR 配置

根据文档语言选择 profile：

```text
中文 CSR：profiles/csr/zh-CN/config.json
英文 CSR：profiles/csr/en-US/config.json
```

生成输入需把 CSR 的章标题结构明确提供给编译器。表和图所在位置前应有对应的一级标题及其章节号路径；CSR 的题注字段才会按 Heading 1 取章号并在一级标题处重置。生成后用 `loom inspect` 检查字段与书签，再在桌面 Word 更新域并检查实际编号。

## 实现代码与配置入口

- CSR profile：`profiles/csr/zh-CN/config.json`、`profiles/csr/en-US/config.json`
- Word 生成与样式应用：`compiler/arachne_loom/generator.py`
- 题注、引用和目录域：`compiler/arachne_loom/fields.py`
- 输入结构校验：`compiler/arachne_loom/validator.py`
- 已有 DOCX 几何规范化：`compiler/arachne_loom/normalizer.py`
- Word 手动验收标准：`docs/acceptance-tests.md`
